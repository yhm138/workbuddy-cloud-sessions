# v1.10.0 — 点开就有、说了不丢

一句话：**拉正文从「等 5 秒」变成「1 秒见正文」，底部写的话再也不会凭空消失，
小程序来源的会话也不会再把你送进客户端的空页面。**

## 为什么改

v1.9.1 修好了「缺少 id」，正文能拉到了，但用起来还有三处别扭：

1. 在底部输入条写一句、回车，会跳到原会话，**输入框却是空的**，刚才写的话像被吞了；
2. 「正在从云端拉取正文…」转圈偏久，明明内容早就到了；
3. 某条会话（`2070359399505326080`）面板能拉到快照，但点「回到会话」进去只显示
   「暂无对话记录」。

## 1. 输入条：先复制、再跳转，一步都不丢

旧链路是「先深链切走 → 800ms 后 `wb:message:fill`」。而 `wb:message:fill` 的真实语义是
把内容推进主窗口的 composer 事件流，**顺手把 `currentConversationId` 置空**（切到新草稿）；
切换途中 composer 还没挂载时，事件直接静默丢弃 —— 于是目标会话没收到，用户看到的就是空输入框。

新链路：

```
① 回车 → 这句话写进本地草稿 + 进剪贴板 + 底部弹出确认条
② 再回车 / 点确认条 → 才真的打开原会话，提示「Ctrl+V 粘一下」
```

- 草稿按会话 id 存在 `localStorage`（`wbcs.drafts`），回列表再点回来还在
- 面板被销毁、宿主吞事件都不影响：剪贴板里一定有一份
- `⋯ → 填上下文` 也改成先复制再 fill

## 2. 回放提速：4.2s → 0.83s（本地实测）

| 改了什么 | 省了多少 |
| --- | --- |
| 空闲收尾 4000ms → 1400ms（`session/load` 回执后 700ms） | **~2.6s** |
| 首帧到达即发 `initialize`（原来死等 600ms） | ~0.6s |
| `initialize` 返回即发 `session/load`（原来死等 300ms） | ~0.3s |
| keep-alive Agent：票据 / SSE / POST 复用连接 | ~0.2s（真机更明显） |
| `ts` 缓存：云端 `updatedAt` 没变就复用，30 分钟内不重放 | 重复打开 **≈0ms** |
| 鼠标悬停 150ms 预取 + 进面板预热 TLS | 点开时基本已在缓存 |

再加一条「感知提速」：新增 `peek` 方法，面板边回放边画（280ms 一次，条数没涨不重绘），
第一段正文 1 秒内就出现，尾部继续补 —— 不用盯着转圈。

诊断区现在会多一行：

```
上次回放  : 0.9s（票据 210 / 握手 120 / 首帧 130 / 回放 380ms） · 42 条
```

## 3. 小程序 / App 来源：不再往空页面里送

`workbuddy-mp` / `workbuddy-app` 来源的会话，本地库里有一条记录（所以侧栏能看到），
但客户端只认自己产生的对话记录，打开就是「暂无对话记录」；完整历史只在云端。

现在：

- 详情页主按钮在这类会话上变成「**网页版打开**」（菜单里另留「回客户端（可能为空）」）
- 列表行 ↗、以及所有走 `openSessionInClient` 的入口，先弹一个说明框，
  默认动作指向网页版
- 输入条在这类会话上，确认条的主按钮也直接给「网页版打开」

## 顺手修的

- **预取的正文被误标成「本机快照」**：预取也是走云端，之前点开详情会误弹
  「快照可能不是最新」。现在按来源标「云端最新」
- 预取深度 3 → 5；`MAX_CONCURRENT` 仍是 2（网关对并发敏感）
- CI 增加 `PAGE_VERSION` 一致性校验（之前只校验四处）
