# v1.11.0 — 面板不大包大揽，只负责「看清楚 + 送你去说」

## 改了什么

**1. 删掉底部输入框（以及它带的一整套东西）**

`#composer`、按会话存的草稿、`wb:message:fill` 调用、回车两步式确认条 —— 全部移除。
面板回归纯只读。

原因说清楚：宿主的 `wb:message:fill` 参数里**没有目标会话**（`sidebarUrl` 写死成空串），
它的真实效果是「切到一个新草稿」。所以「在面板里打字 → 跳到原会话」这条路，
从来就不可能把字带过去。留着一个填不进东西的输入框，比没有更糟。

**2. 正文末尾加一张「继续对话」卡**

```
● 到这里是全部 42 条
面板只读，不能在这儿发消息。要接着说，回原会话 —— 历史和后续都在那边。
[ 回融合会话继续 ]  [ 在网页版打开 ↗ ]  复制链接
```

小程序 / App 来源换个说法（客户端里那条是空壳）：

```
● 到这里是全部 42 条
这条来自小程序，客户端里没有它的对话记录。要接着说，用网页版。
[ 在网页版继续 ↗ ]  回客户端（可能为空）
```

回放中标题会变成「已到 N 条 · 后面还在补」，不会让人以为提前到底了。

**3. 顶栏按钮跟着来源走，点了立刻有反馈**

- 桌面来源：`回融合会话` → `workbuddy://chat/<id>` 深链，同一个 Session
- 小程序 / App 来源：`网页版继续` → 系统浏览器
- 点击后按钮文案变 `正在切过去…` / `正在交给浏览器…`，1.6 秒复原

之前「点了没反应」的真因：宿主的 `setWindowOpenHandler` 只放行 `https:` 并转
`shell.openExternal`，`window.open` 的返回值**恒为 `null`**。浏览器开在后台时，
面板里没有任何变化，看起来就像点击失效。现在一律给按钮级 + toast 双反馈。

**4. 顺手**

- `label()` 加了来源兜底表：部署环境缺 `data.js` 映射时不会再显示 `workbuddy-mp`
- 详情页副标题单行省略，窄屏不再被长副标题挤成两行

## 为什么这样更好

用户对面板的期待只有一件事：**看到客户端里看不到的历史**。
把「说下一句」的入口放在这里，等于承诺一个做不到的能力。

现在的边界很干净：看完 → 点一个明确的地方 → 在原会话里说。
两条路都写在同一张卡片上，不用猜「这条该去哪儿」。

## 升级

```bat
install.bat
```

装完**托盘退出 WorkBuddy 再打开**（service 是启动时 fork 的）。
「数据与诊断」应显示 `service v1.11.0 · pid …`。

## 兼容性

无协议变更，`server/` 的 ACP 回放逻辑与 v1.10.0 完全一致；本版只动面板层。
旧版安装包可以随时回退，已缓存的正文和收藏不受影响。
