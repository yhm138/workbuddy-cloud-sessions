# v1.8.0 — 进面板就自动同步

本次只改一件事：**不用再手动点「同步云端列表」了**。另外把「能不能靠打开会话把最新正文拉到本地」这个问题查清并写进文档。

## 自动同步

点进「云端会话」就会自动拉一遍云端列表，有新会话顺手补正文。触发条件：

| 时机 | 说明 |
| --- | --- |
| 刚打开面板 | 桥接就绪后 1.2 秒 |
| 从别的页面切回来 | 面板重新可见（`IntersectionObserver`） |
| 窗口重新获得焦点 | 切出去再切回来 |

60 秒内只拉一次，不会来回刷。**自动同步失败不弹提示**（只写进诊断，下一次可见时再试），
没有新会话也不打扰——只有真的新增了才弹一句「新增 N 条」。

`⋯ → 同步云端列表` 仍然保留，当作手动重试；`R` 键同样有效。右上角的时间戳语义没变：
显示的就是最近一次成功同步的时间。

## 关于「用打开会话的办法拉最新快照」

结论：**单独靠这条路不行**，三条独立证据：

1. 客户端打开会话时确实做了全量 ACP 回放，但 daemon 落盘的是请求片段，不是完整历史
   （实测：索引 22 条，实际只渲染 8 轮，尾部还缺）。
2. 主进程里 `ensureRuntime()` 第一行就是 `if (transport === 'cloud') return;` ——
   云端会话在客户端里根本不建本地 runtime/缓存，「打开过 = 有本地副本」这个前提不成立。
3. 深链能触发一次真正的全量回放，但它会把窗口切走，而且是一条一次（89 条要点 89 次）。

真正可行的是**给扩展加 service**：宿主 fork 一个 Node 进程，用 `https` 建 SSE，
再用 `wb.invoke('wb:http:get', ...)` 借宿主的 cookie 换 `{link, token}` —— 等于把
`src/acp.js` 搬进客户端，**连扫码登录都不需要了**。门槛是清单里声明
`"service": {"entry": "./server/index.cjs", "process": "fork"}` 和
`"processPolicy": {"server": "fork"}`（和内置 edge-sync 一样），而验证它必须重启客户端。
这条留在下一版，细节见 `docs/PROTOCOL.md` 6.8。
