## 这一版解决什么

上一版（v1.8.0）进面板会自动同步**列表**，但正文还是「本机快照」——因为面板是个 iframe，浏览器里根本没法直连云端：ACP 网关不回 `access-control-allow-origin`，也不 expose `acp-connection-id`，`fetch` 一律被 CORS 拦死。

v1.9.0 把这件事做成了：扩展里 fork 一个真正的 Node service（`server/index.cjs`），用**宿主自己的登录 cookie** 换票据，然后用 `https` 建 SSE 回放历史。

于是：

- **点开会话就是云端最新**，正文顶部标「云端最新 · hh:mm（N 个事件）」
- **不用再扫码**——这条链路借宿主的登录态，不读浏览器的 profile，`wbcs login` 对它没有影响
- **小程序 / 网页版会话**也能看：以前客户端自己打开是「暂无对话记录」，现在面板直接回放
- 列表里的「同步云端列表」和 `⋯ → 补全云端正文` 也都走这条通道，比 v1.8.0 的抓取通道稳

## 面板里长什么样

正文顶部两种提示，别混：

| 提示 | 含义 |
| --- | --- |
| 云端最新 · 21:07 从云端回放（9 个事件） | 真的最新 |
| 本机快照 · 可能不是最新 | service 没起来，降级回快照（行为和 v1.8.0 一致） |

页面底部「数据与诊断」多了一行：

```
云端直连  : service v1.9.0 · pid 41236 · 3 条缓存 · via port
```

看到这行就是通了；写 `不可用 —— …` 后面会带原因。

## 升级（重要）

**装完必须完全退出客户端**（右下角托盘图标右键 → 退出），再打开。

原因是 `service` 是客户端启动时读清单才 fork 的，运行期换文件只会让面板报「插件加载失败」。热更新这次不管用。

已经装过 v1.7.0 / v1.8.0 的，直接覆盖安装即可，`%LOCALAPPDATA%\wbcs` 里的登录态和抓取结果都保留：

```bash
# 源码安装
node bin/wbcs.js deploy --force     # 然后托盘退出、重开
```

或者下载下面的一键包，双击 `安装.bat`。

## 性能与边界

- 单条会话回放：空闲 4 秒收尾、硬超时 60 秒；一次最多 6000 条消息
- 并发 2 条（网关对并发敏感，3 条以上容易 `no_token_401`）
- 内存缓存 3 分钟 / 24 条，3 分钟内重复打开走缓存；`⋯ → 从云端拉最新正文` 可强制重拉
- `Ctrl+F` 会话内查找、全文搜索都覆盖刚拉回来的正文（搜索索引在内存里补一份）
- 进面板时预取最近 3 条还没正文的会话，失败过的记 24 小时，不会每次重试

## 已知限制

- service 只在**本地假宿主**（`test/panel-service.js`）里验证过全链路；真客户端 fork 是否成功、`wb.http.get` 是否真带 cookie，要在你自己机器上看那行「云端直连」
- 客户端版本太旧、或安全软件拦了 fork，面板会自动降级回快照模式，不会白屏
- 仍然只读：不改 `workbuddy.db`、不改 `app.asar`

## 自测

```bash
npm run test:service    # 假网关：票据 / 回放 / 缓存 / force / 失败分支
npm run test:panel      # Playwright 假宿主：面板真的从「云端」拿到正文
NO_SERVICE=1 npm run test:panel   # 降级路径：必须退回快照，不许白屏
```

协议细节（`$resolveLocalRpc` 票据字段、`$invokeLocalRpcFallback` 参数顺序、失败码、踩过的坑）写进了 `docs/PROTOCOL.md` 6.9。
